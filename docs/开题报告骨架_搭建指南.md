# 开题报告骨架 · 搭建指南

> 执行时间：**2026-11-01（周日）下午**，预算 **1.5–2 小时**
> 交付物：`开题报告_骨架.docx`，1 页纸，7 个章节标题 + 每节 3 行要点
> **不要在这一步写正文。** 正文是 11/02 起每天写一点的事。

---

## 零、先明确一件事：骨架和正文是两件事

| | 骨架（11/01） | 正文（11/02 起） |
|---|---|---|
| 要写什么 | 章节标题 + 每节 3 行要点 | 把 3 行要点展开成段落 |
| 字数 | 每节约 30 字，全文 300 字 | 全文 3000+ 字 |
| 用时 | 一次性 2 小时 | 每天 40 分钟，累计一周多 |
| 判断做完了没 | 每节你都能说出"这段我要写什么" | 每节都成段、有数据有引用 |

**骨架的唯一作用**：让后面每天写正文时，不用再想"我该写哪一段"。

---

## 一、Word 里先做三件事（5 分钟）

1. **新建文档，立刻另存为** `开题报告_骨架.docx`，放在 `E:\VS Code\cpp practice\docs\` 下
   （先存盘再写，防止断电丢内容，这是习惯）
2. **打开导航窗格**：菜单 `视图` → 勾选 `导航窗格`
   左边会出现一个目录树，你每加一个标题它就出现一条——**这是你搭骨架时的进度条**
3. **只用「标题 1」样式写章节名**，不要手动调字号加粗
   光标放在行首 → `开始` 标签页 → 样式栏点 `标题 1`
   这样最后 `引用` → `目录` 能一键生成目录，而且结构一眼看得到

> 如果学校后面发了模板，直接把内容粘过去即可，样式会自动匹配。所以现在**不要**纠结字体字号。

## 二、7 个章节 + 每节的 3 行要点

下面每章我给了**引导问题**。你要做的不是回答它们（那是写正文），而是**把它们改写成 3 行短句**，标出"这一节我打算讲这几件事"。

### 第 1 章　研究背景与意义
1. 行人碰撞事故的现状数据（找 1–2 个权威数字，如交通事故中行人占比）
2. 现有车载预警方案的局限（成本高 / 依赖云端 / 夜间失效 —— 选你要打的那一点）
3. 为什么用"嵌入式 + 双目"解决它（低成本、无需联网、能测距离）

### 第 2 章　国内外研究现状
1. 行人检测方向：YOLO 系列演进到 YOLOv8，以及轻量化检测的研究
2. 双目测距方向：立体匹配算法（SGBM 等）与测距精度的研究
3. 嵌入式部署方向：RKNN / 边缘 NPU 上的模型压缩与实时性研究 → 最后一句写"现有工作的不足"，引出你的课题

> 这章将来最长（700 字），也是最需要参考文献的。11/01 只要写 3 行，**别去查文献**，查文献是 11/02–11/08 的事。

### 第 3 章　研究内容与目标
1. 研究内容三条主线：行人检测 / 双目定位测距 / 分级碰撞预警
2. 技术指标（必须可量化）：帧率 ≥ ? fps、测距误差 ≤ ? %、预警响应延迟 ≤ ? ms、有效距离 ? – ? m
3. 拟解决的关键问题：检测框与深度图如何对齐、多目标深度如何平滑、RKNN 量化后精度如何保持

> **技术指标这一行是全篇最重要的 3 行之一**——评委一定问。数字现在可以估，但要写着，后面做出来再校准。

### 第 4 章　系统总体设计与技术路线
1. 硬件组成：RK3568 开发板 + 双目摄像头 + 声光报警模块（蜂鸣器/LED），画一张硬件连接图
2. 软件分层：图像采集 → RKNN 推理（YOLOv8）→ 立体匹配与测距 → 检测·深度融合 → 分级预警 → Qt 界面
3. 技术路线图：从"数据采集"到"实机验证"的流程箭头图，标明每个环节用什么技术

> 这章建议直接画图，文字反而次要。**画图工具用 draw.io 或 PPT 都行，别手绘**——这是要进答辩 PPT 的。

### 第 5 章　关键技术与实现难点
1. 双目标定：内参/外参标定与重投影误差控制（误差大，测距全错）
2. 检测与深度对齐：YOLO 的框是像素坐标，深度图也是像素坐标，如何取框内的有效深度（中位数？去掉异常值？）
3. 实时性与精度平衡：RKNN 量化会掉精度，如何在帧率和准确率之间选参数

> 难点写 3 条就够，**不要写 10 条**。写得越多，答辩被问的概率越大。

### 第 6 章　进度安排
1. 直接用 14 教学周表（本周已排好，见 `毕设作战计划v2`）
2. 标出 3 个里程碑：M1 板子跑通 yolov8 demo（11/15 前）／M2 立体校正+SGBM 能测距（12 月底）／M3 性能优化+完整实验数据（1/17 前）
3. 说明关键路径：模型转换 → 摄像头接入 → 双目标定 → 深度对齐，任何一环延后都直接推到答辩

### 第 7 章　预期成果与参考文献
1. 预期成果：一套可在 RK3568 上运行的实时系统 + 实验数据（帧率/精度/延迟）+ 毕业论文
2. 参考文献 15–20 篇，格式统一（GB/T 7714），分三类：检测 / 双目测距 / 嵌入式部署
3. 说明"与已有工作的区别"一句话：现有工作多在做检测或做测距，本课题把两者在同一块嵌入式板子上做端到端融合并做到实时预警

## 五、四个常见错误（都是别人踩过的）

1. **顺手开始写正文**
   一章写了 800 字，后面没时间 → 骨架没搭完，正文也没写完。**骨架阶段一个字都不展开。**

2. **技术指标写成"较高""较快"**
   "帧率较高"= 没写。必须写"≥ 15 fps"。评委只认数字。

3. **研究现状写成"某某提出了某某方法"的流水账**
   每一条都要落到"它解决了什么 / 它还有什么不足"。**没有"不足"，就没有你的课题。**

4. **手动调字号代替标题样式**
   后面加目录、改格式时会全乱。用「标题 1/2」样式，格式统一改。
